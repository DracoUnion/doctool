# 代码规范

> 来源：《AI 时代程序员开发之道》第 6.3、6.4 节（CheckStyle / PMD / FindBugs / Cppcheck / PyLint 工具维度）

---

```markdown
# {{项目名}}编码规范

## 1. 命名规范
- 变量/函数：{{camelCase / snake_case}}
- 类/组件：{{PascalCase}}
- 常量：{{UPPER_SNAKE}}
- 文件命名：{{规范}}

## 2. 代码风格
- 缩进：{{4 空格 / Tab}}
- 行宽：{{≤ 120 字符}}
- 大括号位置：{{K&R / 独立行}}
- 运算符两侧空格

## 3. 注释规范
- 文件头注释：{{版权、作者、版本、功能}}
- 函数注释：{{参数、返回值、异常、示例}}
- 关键逻辑注释

## 4. 错误处理
- 异常捕获范围
- 日志级别（DEBUG/INFO/WARN/ERROR）
- 错误信息规范

## 5. 安全规范
- SQL 注入防护（参数化查询）
- 敏感数据脱敏
- 认证/授权检查

## 6. 静态检查工具
| 工具 | 语言 | 检查维度 |
|---|---|---|
| CheckStyle | Java | 风格、Google/Sun 规则 |
| PMD | Java | 逻辑缺陷、规则集 pmd-ruleset.xml |
| FindBugs | Java | 潜在 Bug |
| PyLint | Python | 风格、约定 |
| Cppcheck | C/C++ | 静态分析 |

## 7. 代码评审 7 要点
1. 业务逻辑正确性
2. 算法效率
3. 可读性
4. 规范性
5. 扩展性
6. 安全性
7. 漏洞与 Bug
```
